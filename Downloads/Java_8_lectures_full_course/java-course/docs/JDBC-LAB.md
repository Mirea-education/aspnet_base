# Дополнительная работа с PostgreSQL

Для этого маршрута нужны отдельная учебная база PostgreSQL, доступ к ней и официальный драйвер pgJDBC. Основные восемь демонстраций работают без этих компонентов. В среде подготовки JDBC-код скомпилирован, но соединение с настоящей БД не испытывалось.

[Официальная установка драйвера](https://jdbc.postgresql.org/documentation/setup/) · [Транзакции PostgreSQL 17](https://www.postgresql.org/docs/17/transaction-iso.html) · [Ограничения таблиц](https://www.postgresql.org/docs/17/ddl-constraints.html)

## Подготовка окружения

Создайте отдельную учебную БД, например `java_course`, и пользователя `course_user`, которому разрешено создавать и изменять таблицы в этой БД. Способ создания зависит от вашей установки PostgreSQL. Дальнейшие команды предполагают, что сервер доступен на `127.0.0.1` и порту 5432.

Скачайте JDBC-драйвер с [официальной страницы pgJDBC](https://jdbc.postgresql.org/download/), положите jar в `lib` и дайте ему локальное имя `postgresql.jar`. Это имя в командах, а не утверждение о текущей версии драйвера. Сам драйвер в архив не включён.

Настройки читаются из окружения текущего процесса. Пример для bash запрашивает пароль без записи самого значения в команду.

```bash
export COURSE_JDBC_URL='jdbc:postgresql://127.0.0.1:5432/java_course'
export COURSE_JDBC_USER='course_user'
read -r -s -p 'Пароль учебной БД ' COURSE_JDBC_PASSWORD
export COURSE_JDBC_PASSWORD
```

В PowerShell используйте следующий ввод для учебного запуска.

```powershell
$env:COURSE_JDBC_URL = 'jdbc:postgresql://127.0.0.1:5432/java_course'
$env:COURSE_JDBC_USER = 'course_user'
$courseCredential = Get-Credential -UserName 'course_user'
$env:COURSE_JDBC_PASSWORD = $courseCredential.GetNetworkCredential().Password
```

Приложение ожидает пароль в переменной окружения. Это простой учебный способ конфигурации, а не полная система управления секретами. Не добавляйте реальные пароли в исходники или Git.

## Лекция 7 — две связанные SQL-операции

Выполните `examples/07-integration/schema.sql` в учебной БД через psql или привычный SQL-клиент. В варианте psql пароль вводится по запросу.

```bash
psql -h 127.0.0.1 -p 5432 -U course_user -d java_course -f examples/07-integration/schema.sql
java tools/Run.java 07
```

Команда Run компилирует `JdbcDemo` вместе с HTTP-примером. Дальше используйте разделитель classpath своей ОС.

```bash
java -cp "build/07:lib/postgresql.jar" JdbcDemo
```

```powershell
java -cp "build/07;lib/postgresql.jar" JdbcDemo
```

Успешный результат — `TRANSACTION=COMMITTED`. Проверьте данные отдельными SELECT.

```sql
SELECT sku, available FROM course_stock ORDER BY sku;
SELECT request_id, sku, quantity FROM course_orders ORDER BY request_id;
```

На новой схеме BOOK имел остаток 5. После одного успешного запуска с количеством 1 остаток должен быть 4 и должна появиться одна запись заказа. Каждый новый запуск `JdbcDemo` создаёт новый UUID, то есть новую команду.

Передайте количество, превышающее запас.

```bash
java -cp "build/07:lib/postgresql.jar" JdbcDemo 9999
```

Для Windows замените разделитель classpath. Ожидается отказ `Stock unavailable`. Число заказов и остаток должны сохраниться относительно состояния до этой попытки. Это наблюдение нужно подтвердить SELECT, а не только сообщением в консоли.

Схема не восстанавливает остаток при повторном выполнении, потому что начальная вставка использует `ON CONFLICT DO NOTHING`. Для полностью чистого эксперимента используйте новую учебную БД. Не выполняйте удаление таблиц в базе с чужими данными.

## Лекция 8 — постоянное хранилище финального API

Таблицы лекции 8 имеют префикс `course8_` и не используют таблицы отдельной демонстрации лекции 7. Выполните вторую схему.

```bash
psql -h 127.0.0.1 -p 5432 -U course_user -d java_course -f examples/08-service/schema.sql
java tools/Run.java jar
```

Запустите сервер с jar драйвера в classpath. Переменные окружения должны быть заданы в этом же терминале.

```bash
java -cp "build/orders.jar:lib/postgresql.jar" course.orders.app.ServerMain
```

```powershell
java -cp "build/orders.jar;lib/postgresql.jar" course.orders.app.ServerMain
```

В начале должно быть `STORE=postgresql`. Обычная команда `java tools/Run.java server` не добавляет внешние jar, поэтому для этого маршрута используйте явный classpath выше.

Создайте заказ через POST, затем повторите тот же запрос и прочитайте фактический адрес из Location. Команды запросов находятся в [QUICKSTART.md](QUICKSTART.md). Для первого отдельного JDBC-сценария удобно взять ключ `jdbc-lecture-1` и количество 2.

```sql
SELECT sku, price_cents, available FROM course8_stock ORDER BY sku;
SELECT id, request_key, sku, quantity, total_cents, created_at
FROM course8_orders
ORDER BY id;
```

В свежей схеме первая команда уменьшает остаток 5 до 3. Её повтор не должен снова уменьшать остаток. Сохранённый заказ имеет сумму `149990 × 2 = 299980` копеек.

## Программа интеграционной проверки

Следующая таблица — ожидаемый контракт для проверки преподавателем, а не перечень выполненных в среде подготовки испытаний.

| Сценарий | Проверяемое наблюдение |
|---|---|
| Новый допустимый ключ | 201, одна новая строка, остаток уменьшен на quantity |
| Тот же ключ и те же данные | 200, тот же заказ, остаток не изменился второй раз |
| Тот же ключ и другое количество | 409, данные не изменились |
| Не хватает остатка | 409, новая строка заказа не осталась после отката |
| Неизвестный артикул | 404, остатки и заказы не изменились |
| Перезапуск только Java-сервера | Прежний заказ доступен, повтор узнаётся |
| Два клиента с одним ключом | Одна запись заказа и один резерв |
| Два разных ключа на последний товар | Не более одного успешного резерва |

Для конкурентного опыта используйте отдельный заранее подготовленный набор данных. Сравнивайте состояние до и после, а не только HTTP-статусы. Успешное выполнение тестов памяти `java tools/Run.java test` не заменяет эту таблицу.

## Как устроен адаптер

`JdbcOrderStore` выбирает READ COMMITTED, начинает транзакцию и проверяет существующий ключ. Затем получает цену и пытается вставить заказ с уникальным request_key. `ON CONFLICT DO NOTHING` разрешает спор за один ключ через ограничение БД. При проигранной вставке новый SELECT читает сохранённый результат, а содержимое команды сравнивается с исходным.

Для нового заказа условный UPDATE уменьшает остаток. Если обновлено не ровно одно значение, транзакция откатывается вместе со вставкой заказа. Номера identity при этом могут иметь пропуски. Нельзя выводить количество заказов по последнему номеру.

Адаптер не содержит пул соединений, миграции, общую политику SQL-тайм-аутов, автоматические повторы всех ошибок и доставку внешних событий. Конфигурация и поведение при отказе БД должны быть дополнены и проверены перед внешней эксплуатацией.
