# Контракт учебного HTTP API

Сервис работает на `http://127.0.0.1:8080`. Другой порт можно задать при запуске. Реальных платежей нет. Поддерживается резервирование товара BOOK с ценой 149990 копеек за единицу.

## Создание заказа

`POST /orders` принимает `application/x-www-form-urlencoded`. Разрешены ровно три поля. Дополнительные и повторяющиеся поля отклоняются.

| Поле | Договор |
|---|---|
| `key` | От 1 до 64 символов из A–Z, a–z, 0–9, `_`, `-` |
| `sku` | `[A-Z][A-Z0-9_-]{0,31}`, в текущем каталоге существует BOOK |
| `quantity` | Целое число от 1 до 5 |

Тело ограничено 1024 байтами. Ответ использует JSON. Пример успешного результата для двух единиц в свежей памяти приведён ниже.

```json
{"id":"O1","sku":"BOOK","quantity":2,"totalCents":299980}
```

Сумма равна `149990 × 2`. Новый заказ возвращается с `201` и `Location`. Такой же ключ с теми же данными возвращает тот же заказ с `200`. Изменённое содержимое при старом ключе даёт `409` и не изменяет остаток.

## Чтение

`GET /orders/O1` возвращает заказ с указанным идентификатором либо `404`. Клиент должен получать идентификатор из ответа или Location, а не предполагать следующий номер. `GET /health` возвращает `{"status":"UP"}` при работе обработчика, но не проверяет БД.

## Ошибки

| Статус | Код тела | Значение |
|---|---|---|
| 400 | `invalid_request` | Формат или предметное ограничение команды нарушены |
| 404 | `not_found` | Ресурс или товар не найден |
| 405 | `method_not_allowed` | Метод не разрешён, разрешённый указан в Allow |
| 409 | `key_conflict` | Тот же ключ использован для другой команды |
| 409 | `no_stock` | Недостаточно товара |
| 413 | `body_too_large` | Превышен размер тела |
| 415 | `content_type` | Неподдержанный формат тела |
| 500 | `internal_error` | Непредвиденная серверная ошибка |

Сообщение сервера для клиента не содержит SQL, учётных данных или трассировки стека. Непредвиденное исключение записывается через System.Logger.

## Пределы гарантий

В памяти ключи и заказы существуют до завершения процесса. Дополнительный PostgreSQL-адаптер хранит их в БД; его интеграционная проверка описана отдельно. У сервиса нет аутентификации и разграничения доступа к заказам, поэтому он привязан к loopback и предназначен для локальной демонстрации.

При ответе по ключу содержимое команды сравнивается с сохранённым. Срок хранения ключей в учебном примере не ограничен. Вариант памяти не подходит для неограниченного потока запросов и долговременного хранения.

[Семантика HTTP в RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html) задаёт общий протокол. Соответствие предметных причин конкретным статусам в этой таблице является договором данного API.
